================================================================================
 [iOS 앱 버그 리포트] Bluetooth 상태 카드 UI 미갱신 (stale "Connected")
================================================================================

작성일     : 2026-07-08
작성       : QA 자동화 (AK-automation iOS 파이프라인)
심각도     : Major (기기 연결 상태 오표시 — 의료기기 모니터링 신뢰성 문제)

--------------------------------------------------------------------------------
1. 환경
--------------------------------------------------------------------------------
- 기기        : iPhone 13 mini (iPhone14,4)
- OS          : iOS 18.6.2
- 앱          : S-Patch AccurKardia v1.1.2 (com.wellysis.accurkardia.accurkardia)
- 패치        : S-Patch EX, Serial 510131 (BLE 연결, Study 진행 중 상태)
- 검증 도구   : WebDriverAgent(XCUITest) — Bluetooth 라디오 상태는
                설정 앱의 Bluetooth 스위치 value(0/1)를 ground truth로 사용

--------------------------------------------------------------------------------
2. 증상
--------------------------------------------------------------------------------
Bluetooth 라디오가 완전히 꺼진 상태(설정 스위치 OFF, value=0 확인)인데도
앱 메인 화면 Device Status 탭의 "Bluetooth" 카드가 "Connected"를 계속 표시.
포그라운드 복귀 후 60초 이상 관찰해도 갱신되지 않음 (그 이상 방치해도 동일).

--------------------------------------------------------------------------------
3. 재현 절차 (100% 재현 조건)
--------------------------------------------------------------------------------
전제: S-Patch 연결 완료, Study 진행 중, 앱 메인 화면 Bluetooth 카드 "Connected"

 1) 제어 센터를 연다 (우상단에서 아래로 스와이프)
 2) 연결 페이지에서 Bluetooth 타일을 탭한다
    → 타일 표기: 'S-Patch EX 510131' → '연결 안 됨'
    → 주의: 이 상태는 "주변기기 연결 해제 모드"로 BT 라디오는 켜져 있으며,
      앱의 S-Patch BLE 링크는 실제로 유지됨 (앱 카드도 Connected 유지 — 정상)
 3) 제어 센터를 닫고 앱으로 돌아온다 (~2분 관찰, 카드 Connected 유지)
 4) 설정 앱 > Bluetooth 로 이동하여 스위치를 OFF 한다 (라디오 완전 꺼짐)
    → 이 시점에 앱은 백그라운드 상태
 5) 설정 앱에 ~60초 머무른다
 6) 앱으로 복귀하여 Bluetooth 카드를 관찰한다

 [버그] 카드가 "Connected"로 고착 — +0s/+10s/+20s/+30s/+45s/+60s 모두 Connected
        (이때 설정 스위치 value=0, 라디오 OFF 재확인됨)

--------------------------------------------------------------------------------
4. 대조 실험 (버그가 발생하지 않는 조건 — 트리거 분리)
--------------------------------------------------------------------------------
실험 A: 위 절차에서 (1)~(3) 제어 센터 단계 없이, 설정 스위치 OFF + 백그라운드
        60초 후 복귀 → 복귀 즉시 "Disconnected" 정상 표시
실험 B: 설정 스위치 OFF 후 즉시(~8초) 복귀 → 즉시 "Disconnected" 정상 표시
실험 C: 제어 센터 BT 타일 탭 선행 후 (3)~(6) 수행 → 버그 재현 (상기 3절)

→ 결론: "제어 센터 Bluetooth 타일 조작(연결 해제 모드) 선행"이 필수 트리거.
   이 선행 없이 라디오만 꺼지면 앱은 정상적으로 Disconnected 를 표시함.

--------------------------------------------------------------------------------
5. 원인 추정 (개발팀 확인 필요)
--------------------------------------------------------------------------------
iOS에서 제어 센터 BT 타일을 끄면 CoreBluetooth 는 CBManagerState 를
.poweredOff 로 보고하지만 기존 BLE 연결은 유지되는 특수 상태가 됨.
관찰된 동작과 조합하면:

 - 앱이 이 시점의 state 변경(.poweredOn → .poweredOff)을 받고도 링크가
   살아있어 카드를 Connected 로 유지 (여기까지는 표시상 사실과 부합)
 - 이후 설정에서 라디오가 실제로 꺼져 BLE 링크가 끊길 때, 앱이 백그라운드라
   didDisconnectPeripheral / 추가 state 이벤트를 놓치거나,
   "이미 poweredOff 처리를 했다"고 판단하여 상태 머신이 갱신을 스킵하는 것으로 추정
 - 포그라운드 복귀 시(applicationDidBecomeActive 등) BT/연결 상태를 재조회하는
   동기화 로직이 없어 stale UI 가 지속됨

권장 수정 방향:
 - 포그라운드 복귀 시 CBCentralManager.state 와 peripheral 연결 상태를
   재조회하여 카드 UI 를 강제 동기화
 - CBManagerState 전이를 카운트/플래그가 아닌 현재값 기준으로 처리

--------------------------------------------------------------------------------

7. 영향
--------------------------------------------------------------------------------
- 사용자가 제어 센터로 BT 를 껐다가 이후 설정에서 완전히 끄는 일반적 사용
  패턴에서, 앱이 패치가 연결된 것으로 오표시 → 측정 중단을 인지하지 못할 위험
- ECG 데이터 수집이 실제로 중단된 상태에서 UI 는 정상으로 보임
