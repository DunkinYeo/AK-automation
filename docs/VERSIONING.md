# 버전 관리 기준 (Semantic Versioning)

`vMAJOR.MINOR.PATCH` — 판단 기준은 "테스터가 뭘 다시 해야 하는가".

## MAJOR (v2.0.0)
기존 사용법이 깨질 때만.
- 설정 파일/CLI 옵션 비호환 변경, 지원 플랫폼·OS 최소 요건 변경
- 테스터가 기존 ZIP·설정을 버리고 새로 설치해야 하는 변경

## MINOR (v1.1.0)
새 기능. 기존 사용법은 그대로.
- 새 플랫폼 지원(예: iOS), 새 테스트 스위트/워크플로우, 웹 UI 새 기능
- 배포 방식 개선(예: WDA.ipa 번들)

## PATCH (v1.0.x)
버그 수정·안정화만. 기능 추가 없음.
- 크래시/정지 수정, 오탐 수정, 라벨·표시 수정, 문서

## 운영 규칙
- **공유(배포) 전에는 재버전 가능**, 공유 후에는 불가 — 다음 버전으로
- 릴리즈마다: `VERSION` 갱신 → `CHANGELOG.md` 섹션 작성 → 태그 = 릴리즈 시점 커밋 → ZIP 자산은 그 커밋에서 빌드
- 릴리즈 후 수정이 쌓이면 노트에 끼워넣지 말고 **PATCH를 새로 발행** (이번 v1.0.6→v1.1.0은 미공유 상태라 예외적으로 재버전)
- Beta 기능은 버전과 무관하게 릴리즈 노트에 `[Beta]` + 검증 환경 명시
